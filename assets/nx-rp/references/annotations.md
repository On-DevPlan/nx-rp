# annotations · 文件批注 / 评价 / 待办 / 思考

> 加载时机：用户要「给某个文件加批注 / 评价」「记个待办」「看一下文件的批注」，
> 或 agent 需要快速查看文件内容并挂评论时。
> 一句话：面板打开就是 **IDE 三栏**——左工作树（点节点切换中栏）、
> 中文件预览/目录概览、右批注侧栏；点左侧节点上的「+批注」可直接给文件
> **或目录**挂批注。

---

## 一、它是什么

给**任意本机文件或目录**挂批注的独立面板。三类批注：

| kind | 用途 | 交互 |
| --- | --- | --- |
| `review` | 评价（这段代码好/坏、设计对/错） | 纯文本 |
| `todo` | 待办操作 | 有 done 状态，可勾选完成 |
| `note` | 思考（随想、疑点、后续方向） | 纯文本 |

批注可带 `line` 行号锚点——评论链接到文件的具体位置；目录批注无 `line`。

**存储**：按路径分桶，`~/.nx-rp/annotations/<serializePath(file)>.json`。
序列化规则与知识库目录一致（`D:\a_js\js_proj\nx-rp` → `d--a-js-js-proj-nx-rp`），
全 ASCII 跨平台；一个路径一个桶，原子写（pid tmp + rename）。
文件和目录各自一桶——同一路径下文件与目录名相同时也会冲突（serialize 同一串），
**避开办法**：目录与同名文件不要并存于同一父目录。

## 二、文件加载器的渲染铁律

`ann load` 是查看目标文件的入口，四条硬规则：

1. **默认 1000 字符预览**。超过 → `truncated: true` + `body: null`——**拒绝渲染**，
   绝不截半截内容糊弄；如实报告总字符数与建议
2. **二进制拒绝**（前 8KB 含 NUL 即判二进制——二进制进对话是灾难）
3. `--full` 显式才给全文，仍受 **200K 硬上限**；超过连 --full 也不放行
4. **窗口切片**（`--offset` + `--limit`）：永不拒绝，要多少取多少——
   服务端单文件整读（200K 内开销可忽略），窗口切在正确层（web 面板渐进加载用此模式）
5. **目录特化**：路径是目录时返回 `{ isDirectory: true, dirs, files }`，不读 body、
   不走预览铁律——UI 中栏切到「目录概览」展示子项，可点选下钻

## 三、命令

```
nx-rp ann load --file <路径> [--full]                       # 加载文件/目录
nx-rp ann load --file <路径> --offset 1000 --limit 3000     # 窗口切片（渐进加载）
nx-rp ann add --file <路径> --body <内容> [--kind review|todo|note] [--line N]
nx-rp ann list --file <路径> [--kind ...] [--open]          # 该路径的批注（最新在前）
nx-rp ann get --file <路径> <id>                            # 单条详情
nx-rp ann update --file <路径> <id> [--body/--line/--done]
nx-rp ann remove --file <路径> <id>
nx-rp ann browse [--dir <目录>]                             # 工作树（列直接子项）
nx-rp ann todos                                             # 跨路径的全部未完成 todo
```

`--file` 既接受文件也接受目录——目录批注用于「这块代码以后再回头看」之类语境。

## 四、面板：IDE 三栏布局

```
┌─ 工作树 ─────┬─ 文件预览 / 目录概览 ─────┬─ 批注 ──────────┐
│ 📁 src/      │ services.js · 124 字符    │ [note ▾] [...]  │
│   📁 core/   │ ──────────────────────    │ ┌────────────┐ │
│   📄 a.js    │ function loadFile() {     │ │ 想法…      │ │
│ +批注        │   // 1k 字符预览          │ └────────────┘ │
│   📄 b.js    │   ...                     │ [note] a_xyz... │
│              │ [加载更多（还剩 N）]       │ [todo ☐] ...   │
│              │                           │ ─────────────  │
│              │                           │ ▾ 跨文件待办(3)│
└──────────────┴───────────────────────────┴────────────────┘
```

- **左栏**：cwd 目录树。每个节点 `▸` 点开 lazy-load 该层子项——**绝不递归整树**；
  hover 节点露出「+批注」按钮，可给文件/目录直接挂批注。
- **中栏**：选中的文件预览（窗口切片续传）或目录概览（子目录/文件列表，点选下钻）；
  顶部面包屑每段可点回退。
- **右栏**：当前路径的批注列表 + 新增表单；底部折叠区显示跨文件待办，点待办可跳回文件。

## 五、工作树渐进式访问

左侧目录树的设计要点：

- **从 cwd 出发**：组件挂载即查 cwd 直系子项作为根节点
- **lazy-load**：每个目录节点的 `▸` 点开才向服务端发起下一次 `browse` 请求；
  节点状态 `loaded=true` 后，再次点击仅切换 `expanded`，不发请求
- **隐藏项跳过**：`.git`、`.next`、`.nx-rp` 等不进浏览
- **面包屑**：中栏顶置，每段可点切换选中；当前段高亮无下划线
- **支持对目录挂批注**：hover 任意目录节点 → 「+批注」→ 弹窗输入内容和类型
  （note/review/todo）；目录 todo 会出现在跨文件待办里

### CLI 等价

```
nx-rp ann browse                          # 列 cwd 的子项
nx-rp ann browse --dir D:\proj\src        # 列指定目录子项
nx-rp ann load --file D:\proj\src         # 目录 → 概览（dirs/files/totalCounts）
```

## 六、agent 典型场景

- 「帮我看看这个文件，有问题记下来」→ 面板左栏点开 → 中栏预览 → 右栏「评价」
- 「这事记个待办」→ 选中文件 → 右栏「待办」类型 → 输入 → 添加
- 「给这个目录加一条提醒」→ hover 左栏目录节点 → 「+批注」→ note/todo
- 「我现在有哪些没做完的事」→ 右栏底部折叠区「跨文件待办」→ 点条目跳回文件
- 「从工作目录开始找文件」→ 左栏按需展开目录 → 点文件选中
- 「同目录下所有文件统一待办」→ 给目录挂一条 todo 批注（CLI：`ann add --file <目录>`）

## 七、边界（不变量）

- 批注是**短评论**（≤4000 字符）——长文/成体系的知识请进 doc 域（文档与召回）
- 批注挂在**绝对路径**上；路径移动后批注不会自动跟随（重新 add 即可）
- `done` 只属于 todo；对 review/note 设 done 会被拒绝
- `line` 只对文件批注有意义；对目录批注设 line 仍可存但不渲染
- **目录浏览/树形展开绝不递归**：单层 `readdir`，点节点才发起下一次请求——避免任何全盘扫描
- **目录与同名文件**：serialize 同一路径串，桶冲突——避免同名并存
